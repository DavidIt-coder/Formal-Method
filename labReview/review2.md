# Lab 2 实验回顾：命题逻辑与 SAT 求解

实验报告：[lab2/report.md](../lab2/report.md)

**实验主线：把需求写成逻辑和 CNF → 用 MiniSAT 求解 → 将结果代回需求检查 → 进一步判断解的数量和编码是否等价。**

## 环境检查：确认 MiniSAT 能正常求解

先在 PowerShell 中运行，遇到找不到命令的问题，随后在 WSL / Ubuntu 中安装并运行 MiniSAT。按照手册，先用 `1 0` 求得 x1 为真的模型，再把子句改为 `-1 0`，得到 x1 为假的模型；两次都是 SAT。当前文件保留的是第二步的版本。

## 任务 1：理解 DIMACS，并解释配置为什么有解或无解

**过程：** 用 S、L、D、F、P 表示服务器模式、本地模式、数据库、文件存储和持久化，把八条业务规则逐条对应到逻辑公式和 DIMACS 子句。运行 `base.cnf`，把模型 `1 -2 3 -4 5 0` 还原为“启用服务器、数据库和持久化”，再逐条检查八条规则。

接着做两个变体：增加 `1 0` 得到 `server_only.cnf`；把 `5 0` 换成 `-5 0` 得到 `no_persistence.cnf`。

**思路与结果：** 服务器版本仍然 SAT，虽然输出模型相同，但它排除了本地模式方案。禁止持久化后得到 UNSAT，原因是“禁止持久化 → 数据库和文件存储都不能开 → 服务器和本地模式都不能开”，与“至少开启一种运行模式”冲突。求解结果必须结合变量含义和依赖关系解释。

## 任务 2：给人物陈述建模，并证明解唯一

**过程：** 用 A、B、C、D、E 表示五个人是否诚实，以“人物诚实 ⇔ 其陈述为真”建立约束。例如 Alice 说 Bob 与 David 身份不同，因此写成 `A ↔ ((B ∧ ¬D) ∨ (¬B ∧ D))`，再拆开双向等价、转换为 CNF。加上“至少两人诚实、至少两人说谎”，得到 24 条子句。

运行 `honesty.cnf` 得到 `-1 -2 3 -4 5 0`。将全部文字反号，加入阻塞子句 `1 2 -3 4 -5 0`，更新子句数后再次求解。

**思路与结果：** 第一次 SAT，阻塞后 UNSAT，说明原问题只有一个解：Carol、Eve 诚实，Alice、Bob、David 说谎。关键是第二次求解排除了存在其他模型的可能，不能只凭找到一个模型就认定唯一。

## 任务 3：自己建立一个选课模型

**过程：** 编写并保存 `SelectClassPrompt.txt`，让 LLM 生成课程表、变量、需求、CNF 和候选方案。随后逐项核对：16 个变量各表示是否选一门课，18 条子句表达必修、已通过课程不再选、配套课程依赖、时间冲突、至少选一门、至多选一门和条件组合。

整理“需求—子句”对照表，重点检查全部时间冲突和课程依赖；将 LLM 的 12 门课方案逐条代入。再运行 `selection.cnf`，把 MiniSAT 返回的 9 门课方案还原为选课安排，并重新检查各条需求。

**思路与结果：** 两份不同的方案都满足需求，说明存在多个合法方案。LLM 提供的是候选编码和方案，需要自己核对，再由实际求解和回代检查支持结论。

## 任务 4：写一个检查具体赋值的 C++ 函数

**过程：** 在 `lab2_solution.cpp` 中实现 `satisfiesCnf()`：外层遍历子句，内层遍历文字；按文字绝对值找到变量，正文字取原值、负文字取反。一个子句找到真文字就通过；任一子句全部为假就返回 false；全部通过才返回 true。

用 `test_42.cpp` 设计六个测试，覆盖正文字、负文字、单子句、多子句以及满足和不满足的赋值，结果为 **6/6 通过**。

再用 `test_fixed.cpp` 检查题目指定的 `{{1, 2}, {-1, 3}, {-2, -3}}`：赋值 `{1,0,1}` 时为 true，只把 x3 改为 false 后变为 false，失效的是第二个子句 `¬x1 ∨ x3`。程序还直接计算原始公式，与函数结果独立对照。

**思路：** 子句内部是“或”，子句之间是“且”。测试要实际计算并比较结果，不能直接打印预设结论。4.2 的自选用例与 4.3 的固定用例是两份不同的 CNF。

## 任务 5：不断阻塞旧模型，枚举所有测试策略

**过程：** 用 U、I、S、C 表示单元测试、集成测试、静态分析和覆盖率，先对原始四条规则求解。每找到一个完整模型，就把它的全部文字反号组成一条阻塞子句，加入文件并更新文件头，再次运行 MiniSAT。

前七次找到七个不同方案，第八次得到 UNSAT。用 `test_strategy_check.cpp` 检查这七个模型都满足原始规则，而且互不重复。

随后从原始四条规则重新开始，增加 `3 0`，要求必须执行静态分析，再完整枚举。

**思路与结果：** 阻塞子句恰好排除当前完整赋值，所以最终 UNSAT 表明没有遗漏其他合法模型。加入静态分析要求后，方案从 **7 个减少到 2 个**：两者都执行单元测试和静态分析，不收集覆盖率，区别仅在是否执行集成测试。

实验中还区分了三个数量：文件里的子句数、MiniSAT 内部保存的子句数、剩余模型数。它们不是一回事。当前两个策略 CNF 都保存了加入全部阻塞子句后的最终状态，因此直接运行应得到 UNSAT。

## 任务 6：判断两份写法不同的 CNF 是否等价

**过程：** 先运行 `encoding_a.cnf` 和 `encoding_b.cnf`，两者都得到 SAT。但这只能证明各自有解，于是在 `test_equivalence.cpp` 中枚举六个变量的全部 **64 种赋值**，每次分别调用 `satisfiesCnf()` 比较 A、B。

原始 A、B 各有 **3 个模型，区分赋值为 0**，所以等价。再用分配律、矛盾律和同一律解释子句拆分：

```text
(K ∨ x) ∧ (K ∨ ¬x) ≡ K ∨ (x ∧ ¬x) ≡ K ∨ false ≡ K
```

最后删除 B 中的 `1 2 4 0`，得到 `encoding_b2.cnf`，并在测试代码中同步删除对应子句后重新检查。修改后的 B 有 **5 个模型**，新增两个区分赋值，按 A、W、D、C、L、M 排列为 `000000` 和 `000011`，即“全部关闭”和“只开日志与监控”。它们都违反原始 A 中“API 与 Web 至少启用一个”的要求。

**思路：** 等价看的是每种赋值下的真假是否一致，不看子句数量，也不能仅凭两者都 SAT 判断。实验中修正了计数变量未初始化的问题；6.4 完成后又把测试代码恢复为原始 A/B，因此当前直接运行会得到等价的结果。
